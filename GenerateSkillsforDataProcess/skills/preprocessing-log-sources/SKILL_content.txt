  merged fault chunks, log_index, and fault_index stored under processed_data/.
  Use when log files have been sorted into source_file/ and need to be structured
  before chunking, or when specific log files have been updated.

# Purpose

Parses raw log files into structured segments with configurable merge windows,
producing log_index and fault_index that enable downstream chunking and
knowledge graph construction for operational fault analysis.

---

# Trigger

**Use this Skill when:**
- source_file/ contains new or updated log files ready for preprocessing
- Pipeline Phase 1 is running for log data type
- User requests reprocessing of a specific log file with custom merge parameters

**Do NOT use this Skill when:**
- source_file/ has not been populated yet (run sorting-raw-files first)
- Only Excel or PDF data needs preprocessing (use the respective skill)

---

# Workflow

[ ] Step 1: 检查 Log 源文件
    - ⚠️ Tool needed: `file-system-mcp:list_files(`path=data_prepare/source_file/, pattern=**/*.log)
    - If 0 log files found → return warning "No log files found in source_file/, skipping"
    - If --file specified → verify that file exists, return error if not found

[ ] Step 2: 执行 Log 预处理
    - ⚠️ Tool needed: `data-pipeline-mcp:run_script(`
        script=scripts/phase1_preprocess_log.py,
        args=[
          "--file", <file> (optional, filename without extension),
          "--before", <before> (optional, segments before fault marker),
          "--after", <after> (optional, segments after fault marker),
          "--gap", <gap> (optional, seconds threshold for merging adjacent events)
        ]
      )
    - If script exits non-zero → return stderr as error message, stop

[ ] Step 3: 验证输出并返回结果
    - ⚠️ Tool needed: `file-system-mcp:list_files(`path=data_prepare/processed_data/, pattern=log_cache/**,log_index*,fault_index*)
    - Return: {processed_files: N, outputs: ["log_cache/", "log_index", "fault_index"]}

**Error handling:**
- If --file points to nonexistent file → return "File not found: <filename>.log in source_file/"
- If log format is unrecognized → log warning per file, continue with parseable files
- If output log_cache is empty → return warning "No segments extracted, check log format"

---

# Scripts

**phase1_preprocess_log.py** — Parses log files into structured segments and index
- Execute: `python scripts/phase1_preprocess_log.py [options]`
- Input: source_file/*.log (hardcoded base dir)
- Output: processed_data/log_cache/ (segments), log_index, fault_index
- Options:
  - `--file FILE` / `-f FILE`: process only the specified filename (without extension)
  - `--before BEFORE`: segments to include before a fault marker
  - `--after AFTER`: segments to include after a fault marker
  - `--gap GAP`: seconds threshold — events within this gap are merged into one segment

**common_schema.py** — Shared data schema definitions used by pipeline scripts

---

# Constraints

- NEVER modify or delete source log files in source_file/
- This skill is READ (source_file/) + WRITE (processed_data/) only
- When --file is not specified, all log files in source_file/ are processed
- Output must include: processed_files count, list of output artifacts
