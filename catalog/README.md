# catalog/

This directory contains the published **Capability Catalog** — the contract
between the Skill/Tool Registry and workflow compilers.

## `catalog.snapshot.json`

Generated by `scripts/publish_catalog.py` from the registries and the shared
system definition. Only **`approved`** and **`restricted`** assets are callable.
Every descriptor carries a version and digest so consumers can create a lockfile.

### Key guarantee

> A workflow package MUST NOT contain any Skill or Tool absent from its pinned
> Catalog snapshot. Runtime code consumes `registry.lock.json`; it does not read
> the Registry branch or resolve new assets during node execution.

### Schema

```json
{
  "schema_version": "2.0.0",
  "generated_at": "<ISO-8601 timestamp>",
  "source": { ... registry versions ... },
  "summary": {
    "allowed_skills": 30,
    "allowed_tools":  15,
    "excluded_skills_by_status": { "draft": 0, "deprecated": 0 },
    "excluded_tools_by_status":  {}
  },
  "skills": [ { "name", "version", "status", "risk_level", "digest", ... } ],
  "tools":  [ { "name", "version", "status", "risk_level", "digest", "endpoint", ... } ],
  "excluded": { "skills": {}, "tools": {} }
}
```

### Consumption pattern

The consuming workflow compiler resolves names and writes a deterministic
`registry.lock.json` containing the snapshot digest and each asset digest.

### Regeneration

```bash
# Local
python scripts/publish_catalog.py

# CI (automatic on every push to master/main that modifies a registry file)
# See .github/workflows/skill-ci.yml — Stage 3
```

### Status enforcement

| Status | Appears in catalog? | Compiler behaviour |
|--------|----------------------|-------------------|
| `approved` | Yes | Fully callable |
| `restricted` | Yes | Callable with additional access checks |
| `draft` | No | Invisible to runtime |
| `submitted` | No | Invisible to runtime |
| `needs_revision` | No | Invisible to runtime |
| `deprecated` | No | Runtime should reject calls and log a warning |
| `retired` | No | Runtime must raise an error |
